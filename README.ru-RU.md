### Operational Superset для Pi Coding Agent

**Наблюдайте, управляйте и координируйте агентов Native Pi в одной настольной рабочей области.**<br>
Каждого агента по-прежнему запускает Pi. Pi-Harness добавляет вокруг него рабочую область, историю запусков, восстановление и команды агентов,<br>
а ваши сессии, конфигурация, Skills и расширения Pi продолжают работать как в приложении, так и вне его.

## Нужен ли вам Pi-Harness?

[Pi Coding Agent](https://github.com/earendil-works/pi) хорошо работает в терминале. Но на реальных проектах быстро хочется большего: видеть, что на самом деле сделал каждый запуск, возвращаться к рабочему состоянию, если запуск пошёл не так, и делить крупную задачу между несколькими агентами. Pi-Harness собирает всё это в одном настольном приложении поверх того же Pi:

- **Каждый запуск на виду**: Runs, Trace, Replay и Evaluation показывают действия инструментов, сравнивают результаты и помогают разбирать сбои по записанным данным.
- **Работу можно восстановить**: Policy, Budget, Checkpoints и Recovery задают права инструментов и лимиты расходов, сохраняют точки восстановления и позволяют продолжить, ответвить или повторить работу.
- **Координация команды**: Agent Teams, Task DAG и Worktrees распределяют зависимые задачи, передают результаты между агентами Pi и разделяют изменения каждого агента.
- **Всё на Native Pi**: цикл агента, сессии, контекст, инструменты, модели и рассуждения выполняет Pi. Pi-Harness управляет ими визуально, а Pi можно и дальше использовать вне приложения.

Pi-Harness подойдёт, если вы используете Pi на реальных проектах и хотите видеть, направлять и координировать его работу из одного окна. Если вам достаточно одного чата в терминале, хватит и самого Pi.

Работает на macOS, Windows и Linux. Установщики сообщества включают Pi и Node.js, поэтому заранее ничего устанавливать не нужно.

## Быстрый старт

**1 · Установка.** Скачайте установщик для своей системы на **[GitHub Releases](https://github.com/wangmiaozero/pi-harness/releases)**:

| | |
| :-- | :-- |
| **macOS** | `.dmg` для Apple Silicon (`arm64`) или Intel (`x64`). Откройте его и перетащите Pi-Harness в «Программы» |
| **Windows** | Установщик `.exe` для x64. Запустите его и выберите папку установки |
| **Linux** | `.AppImage` для x64. Сделайте файл исполняемым и откройте его |

```sh
chmod +x "./Pi-Harness-VERSION.AppImage"   # замените VERSION на скачанную версию
./Pi-Harness-VERSION.AppImage
```

<sub>Установщики включают Pi, Node.js, npm и npx: не нужно устанавливать Pi или Node.js, клонировать этот репозиторий или устанавливать pnpm. Проверка выпусков охватывает macOS Apple Silicon, macOS Intel, Windows x64 и Linux x64; платформы каждого выпуска определяются по результатам проверки. Проверка для Linux ориентирована на Ubuntu 24.04; другие дистрибутивы, FUSE и интеграцию с рабочим столом нужно проверять отдельно. Windows и Linux ARM64 — предварительные платформы. У более старых пакетов могут быть другие требования, поэтому следуйте примечаниям к скачанной версии. Сборки для macOS подписаны ad-hoc, а установщики Windows не подписаны: см. <a href="#verify-your-download">Проверка загрузки</a>.</sub>

**2 · Проверка среды.** Запустите Pi-Harness и проверьте среду на странице обзора.

**3 · Добавление провайдера.** Настройте провайдера, проверьте подключение и выберите модель. Для доступа к модели могут понадобиться учётные данные, а провайдер может взимать плату.

**4 · Начало работы.** Начните отдельный чат или откройте проект, затем начните или продолжите сессию Pi и работайте с разговорами, файлами и Git в одном окне. Чтобы просмотреть запуски или координировать команду, откройте **Рабочая область → Инструменты → Harness / Агенты**.

### Проверка загрузки

Выпуски сообщества бесплатны. Пакеты для macOS используют **подпись ad-hoc без Apple Developer ID и нотариального заверения**. Установщики Windows **не подписаны**, и SmartScreen может показать предупреждение. Прежде чем разрешить запуск приложения, проверьте официальный источник загрузки и контрольную сумму. Если macOS блокирует первый запуск, используйте **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть** для этого приложения. Не отключайте системную защиту.

Скачайте `SHA256SUMS` вместе с установщиком, вычислите хеш своего файла и сравните его со значением для того же имени файла в списке (замените `VERSION` и архитектуру на значения своей загрузки):

```sh
shasum -a 256 "Pi-Harness-VERSION-arm64.dmg"   # macOS
sha256sum "Pi-Harness-VERSION.AppImage"        # Linux
```

```powershell
Get-FileHash ".\Pi-Harness-Setup-VERSION.exe" -Algorithm SHA256   # Windows
```

<sub>SHA256 подтверждает совпадение со списком контрольных сумм, но не доказывает личность издателя независимо. Пользуйтесь официальной страницей <a href="https://github.com/wangmiaozero/pi-harness/releases">GitHub Releases</a>, а о предполагаемых уязвимостях сообщайте конфиденциально на <a href="mailto:tuziling84@gmail.com">tuziling84@gmail.com</a>. Сборки сообщества проверяют наличие новых версий в приложении и открывают страницу Releases для ручного скачивания и установки на всех платформах. Автоматическая установка остаётся выключенной, пока не проверена установка между версиями, а существующие установки сохраняют прежнее поведение обновлений. См. <a href="docs/release/community-release.md">Community Release</a> и <a href="docs/release/update-strategy.md">подробности об обновлениях</a>.</sub>

## Как всё устроено

Pi отвечает за выполнение и нативные сессии. Harness наблюдает за каждым запуском и применяет вокруг него политики, бюджеты, контрольные точки, восстановление и оценку. Команды агентов используют тот же движок выполнения Pi. История разговоров и архитектура проекта — инструменты рабочей области, а темы меняют внешний вид. Схема показывает связи модулей, а не наследование классов.

```mermaid
flowchart TD
    subgraph Desktop["Pi-Harness для рабочего стола"]
        W["Визуальная рабочая область"] --> H["Панель управления Harness"]
        A["Agent Teams / Task DAG"] --> H
        W --> G["Файлы / Git / Worktrees"]
        A --> G
        C["Провайдеры / Модели / Skills / MCP"]
    end
    H --> P["Native Pi Coding Agent"]
    C --> P
    P --> M["Провайдеры моделей"]
```

### Рабочая область, файлы и Git

### Координация нескольких агентов

Откройте **Рабочая область → Инструменты → Агенты**, чтобы координировать агентов Pi с помощью повторно используемых команд и шаблонов. Назначайте задачи с зависимостями и приоритетами, запускайте их вручную, последовательно или параллельно, передавайте результаты и артефакты следующей задаче и добавляйте этапы проверки. Worktrees разделяют изменения каждого агента. Бюджеты, подсказки о конфликтах, а также пауза, продолжение, остановка, повтор, пропуск и переназначение помогают управлять работой.

### Карта архитектуры проекта

Откройте Architecture в рабочей области, чтобы изучить модули, зависимости, точки входа и ссылки на исходный код. Фильтруйте по пакету, выделяйте модуль, листайте карту, меняйте масштаб или включайте полный экран. Сохраняйте снимки анализа, смотрите, когда изменения исходников делают их устаревшими, и экспортируйте JSON, автономный HTML или текущий вид в PNG.

<a id="realtime-voice"></a>

### Голос в реальном времени

Разговаривайте с рабочей областью через **OpenAI Realtime, Gemini Live или Codex Live**. Используйте поддерживаемую учётную запись провайдера или отдельный API-ключ; Codex Live использует существующий вход Codex в Pi. Доступность службы и стоимость зависят от вашего аккаунта.

1. Откройте **Настройки → Голос в реальном времени**, включите голос, выберите службу и аккаунт и сохраните.
2. В разговоре рабочей области нажмите кнопку звуковой волны рядом с полем сообщения.
3. Проверьте целевой разговор и необязательную передачу контекста, выберите **Начать голос в реальном времени** и разрешите доступ к микрофону.
4. Отключайте микрофон, смотрите расшифровку или завершайте звонок с помощью плавающих элементов управления, даже после перехода на другую страницу.

Передача недавнего контекста по умолчанию выключена. Если её включить, передаются только последние шесть текстовых сообщений, без вложений и результатов инструментов. Рабочие запросы из звонка отправляются в рабочий разговор только после вашей проверки.

### Темы и собственное оформление

Выбирайте классические палитры, темы Ming, Starship Cockpit, фоны macOS 27 или импортированное оформление. Новые установки начинают с темы **Мягкий светлый**. Темы персонажей и настольные питомцы — необязательные наборы. Откройте **Настройки → Рынок ресурсов**, чтобы устанавливать наборы `@piharness` по одному из каталога GitHub. 3. Импортируйте готовый проект через **Настройки → Тема → Импортировать тему**.

Многоязычный шаблон содержит рекомендации по цветам, превью, обоям и необязательному изображению персонажа. Храните оформление в отдельном репозитории, чтобы обновлять и распространять его независимо.

### Harness Plugins

**Plugin SDK v1.0.0 · Входит в Pi-Harness начиная с v2.2.6.** Плагины расширяют операции вокруг агента — наряду со способами расширения самого Pi:

| Расширение | Назначение |
| :-- | :-- |
| **Pi Extensions** | Расширяют самого агента Pi |
| **Skills** | Дают агенту инструкции и знания о рабочих процессах |
| **MCP** | Подключают агента к инструментам и внешним сервисам |
| **Harness Plugins** | Расширяют операции Pi-Harness вокруг агента |

Добавляйте **Harness Event Subscribers, Custom Evaluators, Trace Exporters и Agent Team Templates**. Оценки носят вспомогательный характер, экспорт использует разрешённые данные JSON, а шаблоны команд создают ожидающие процессы, которые вы проверяете и запускаете сами. Попробуйте поддерживаемые примеры SDK: [Run Metrics](examples/harness-plugins/run-metrics/plugin.json), [Quality Evaluator](examples/harness-plugins/quality-evaluator/plugin.json) и [Team Template](examples/harness-plugins/team-template/plugin.json).

В сборке из исходников откройте **Рабочая область → Инструменты → Harness → Harness Plugins → Установить локальный плагин**, выберите его папку, проверьте разрешения и включите его. Установка не выполняет код. Исполняемым плагинам нужно явное нативное подтверждение доверия: **отдельный процесс не является защитной песочницей; одобренный код Node может получить доступ к вашему компьютеру**. Для недоверенного содержимого используйте декларативные шаблоны.

[Разработка и установка](docs/plugins/getting-started.md) · [Архитектура](docs/plugins/architecture.md) · [SDK API](docs/plugins/api-reference.md) · [Граница безопасности](docs/plugins/security.md)

### Также

- **Проверка среды**: проверяйте Node.js, npm, PATH, Pi Coding Agent и текущую конфигурацию; устанавливайте, обновляйте или восстанавливайте Pi там, где это поддерживается, изучайте диагностику и управляйте резервными копиями конфигурации.
- **Среды выполнения**: встроенные среды Pi и Node работают сразу, а в настройках можно выбрать системную или собственную среду.
- **Обновления приложения**: проверяйте наличие новых версий прямо в приложении.
- **Восемь языков**: English, 简体中文, 繁體中文, 日本語, 한국어, Русский, Français и Deutsch.

## Разработка

Установите **Node.js 24 LTS (≥ 24.22.1)** и **pnpm 9.12.1**, затем выполните:

```sh
git clone https://github.com/wangmiaozero/pi-harness.git
cd pi-harness
pnpm install --frozen-lockfile
pnpm dev
```
